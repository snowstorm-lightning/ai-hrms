# AI-HRMS｜人机共生的人力资源智能操作系统

## 方案说明

本项目选择作业五「自定义赛道」，命题为“用AI重新定义HRMS”。

线上体验入口：`https://hrms.snowstormlightning.top/login`
账号和密码均为：`12345678900`

我想解决的是HR每天真正卡住的事：制度散落在不同文档里，员工问题要反复确认口径；考勤、请假、招聘、培训、绩效各自成表，很多关键节点还要靠人记住下一步；AI虽然能生成建议，但如果看不到它参考了什么、风险在哪里、谁确认过，HR很难放心使用。AI-HRMS希望把传统HRMS从台账和审批工具，升级成一个能连接人、组织知识、智能体和审计记录的工作空间。

产品从首页工作台展开。HR打开系统后，可以看到待办请求、考勤异常、招聘进展、成长任务、AI建议、知识引用和审计线索。AI指挥中心支持用自然语言提出任务，例如生成新人30天成长计划、分析考勤异常、检查某条建议是否需要人工复核；系统返回内容时，会同步给出风险等级、置信度、引用资料、工具预览和确认要求。知识库管理制度资料，标注可信等级、敏感级别和可见范围，让AI回答能说明依据来自哪里。视觉助手支持圈选页面上的菜单、卡片、表格行或按钮，像身边同事一样解释“这是什么、该去哪、为什么要确认”。智能体运行中心展示任务从输入、计划、工具调用到人工确认的过程，审计中心把AI回答、知识引用、工具预览、人工复核和业务事件串成证据链。

业务上，系统保留完整HRMS体验，覆盖组织员工、员工事务、招聘生命周期、成长绩效和考勤态势。员工可以查假勤余额、签到签退、提交请假、补卡、外勤和报销；主管与HR可以在请求与审批中完成提交、复核、批准、驳回和取消。请假批准会写入假勤台账，补卡和外勤会更新考勤汇总并留下审计记录；涉及处罚、绩效影响、录用和薪资等高影响事项时，系统只提供依据和建议，关键判断仍由人负责。

共进学习舱是项目的亮点之一。它把员工使用AI的过程变成可复盘的成长记录：员工在真实任务中学习提示词、上下文、知识检索、幻觉检查、工具调用和复盘方法，并把提示词、AI输出、人工修订、验证方式和复盘结论沉淀为成长证据。

技术实现上，前端使用React和AntDesign，保证企业级系统的稳定性和专业感；后端使用Go负责权限、可见范围、工作流和审计；PostgreSQL保存组织数据、审批任务、请假台账和打卡日志；Python服务作为模型调用和任务编排的扩展边界。演示阶段使用可控的模拟AI，保证线上体验稳定，也避免把敏感HR数据发送到外部模型。

迭代上，项目先完成基础HRMS，再补充知识库、AI指挥中心、智能体运行、审计中心、视觉助手和共进学习舱，逐步形成“业务办理—AI建议—人工确认—审计留痕—成长复盘”的闭环。效果评估主要看五点：核心流程能否跑通，AI建议是否有依据，HR协同是否更高效，高影响动作是否留下复核记录，员工使用AI的过程能否沉淀为成长资产。AI-HRMS的目标很直接：让HRMS从静态台账变成会解释、会提醒、会留痕、懂边界的工作空间，让HR和员工在AI时代更稳妥、更高质量地完成工作。
