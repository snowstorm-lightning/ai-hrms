# RAG Constraints

## Direction

Use PostgreSQL plus `pgvector` for the first RAG storage path.

Embeddings are generated by the Python agent boundary. Go owns ingestion
authorization, document scope, retrieval filters, and audit logging.
DeepSeek chat configuration and embedding configuration are independent; do not
reuse chat provider settings as embedding settings.

## Access Control

RAG retrieval must apply the same organization scope rules as normal business APIs.

## Document Scope

RAG documents can be global, legal-entity scoped, or organization-unit scoped.

## Runtime Rules

- Filter by scope, document status, effective dates, and sensitivity before returning citations.
- Chunk documents with heading-aware, sentence-aware splitting, conservative body
  size, overlap context, and document/section prefixes before embedding. See
  `docs/rag-chunking.md`.
- Use vector-first retrieval when embeddings are available; lexical fallback is allowed only as a resilience path.
- Do not index HR PII by default.
- Treat cloud embedding providers as external. Internal/restricted/high-impact
  text must be blocked before it leaves the system. Trusted local embedding
  endpoints should use `AI_EMBEDDING_PROVIDER=local-openai-compatible`.
- Clean prompt-injection text during ingestion.
- Log retrievals with query, resolved scope, citations, and refusal reason.
- First connector path covers direct text upload, HTTP(S) URL fetch, and local file/directory reads.
- Local file/directory reads require `AI_HRMS_INGEST_ROOT` and must stay inside that root.
